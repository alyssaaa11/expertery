# New Forge goal: same quality, many times cheaper and faster, private (2026-10-29)

**Summary**: decision (user, 2026-10-29, in chat): Forge's claim changes from "training makes Glimmer more correct" to
**"training makes Glimmer just as correct as Glimmer + every fair cheap fix, but many times cheaper and faster, and
it runs privately"**. Why: smarter models with retries and self-checks may reach 80%+ anyway, so an accuracy-only gap is
risky. The cost and speed claim survives that.

## Honest framing
- Not new as a method: training a model to be cheaper and faster is distillation, a known technique. What is ours:
  every training example is checked automatically by the CadQuery referee, the comparison is against the strongest
  fair baseline, and the result is an end-to-end private tool with a proof report.
- The user's pitch line fits: a trained Glimmer with a short prompt vs Glimmer + long hints/examples/retries = far
  less input per call, one try, offline.

## Fair cheap fixes for the baseline arm (B-max), all usable by a real company
1. The B2 hint sentence. 2. reasoning_strength high (never set before: the first test ran on the default). 3. Retry with
the CadQuery error message. 4. Self-check: the model sees its own part's measured size and position and compares them
with the request numbers (no reference answer). 5. 2-3 solved worked examples in the prompt. 6. Up to 3 rounds in total.
Not allowed: anything that uses the reference answer (that would be cheating).

## Measures (per arm, on the 30 held-out CadQuery jobs)
Pass rate, tries per job, input + output tokens per job, wall time per job, $ per correct part.

## Kill rule (hypothesis until frozen in a PLAN before the final exam)
GO for the claim only if the trained Glimmer (one try, short prompt) reaches **≥ B-max pass rate − 5 points** AND is
**≥ 3× cheaper or ≥ 3× faster per correct part**. Otherwise report it honestly.

## Steps (each paid step needs the user's yes)
1. Muse Code: B2 sandbox + B-max arm (retry loop, self-check, reasoning setting, examples). ~$0.8-1.2.
2. Baseline run: plain Glimmer, hint only, B-max; Spark as reference. ~$1.5.
3. Factory: new practice job families (no overlap with the exam) → Spark solves → the referee keeps only correct ones. ~$3-8.
4. LoRA smoke test, then one training run (H100). ~$5-6.
5. Final exam: trained Glimmer vs B-max vs Spark. ~$1.5.
Total ≈ $12-17 on top of ≈ $9.8 spent → ≈ $22-27 of $30.

## User tweaks (decision, 2026-10-29, via hivey, with "YES 1")
1. **Dev set:** all training choices (epochs, checkpoint, LoRA settings) are made on ~20 held-out factory practice
   jobs, never on the 30 exam jobs. The exam is touched once, at the final exam. The B2 hint and the B-max examples must
   not come from exam jobs. Checked 2026-10-29: the hint is general; the 3 examples are new families
   (`experiments/bmax/examples.py`, verify → 3× OK).
2. **Cheap one-try arm:** the "≥ 3× cheaper" bar is almost automatic against a multi-round B-max, so the final exam also
   runs **Glimmer + hint, one try** (= arm B2). The trained Glimmer must clearly beat it at about the same cost. Final
   chart: accuracy vs $ per correct part for every arm (trained should sit top-left).
3. **Uncertainty:** a paired bootstrap 95% CI for trained vs B-max and trained vs the one-try arm. 5 points = 1-2 jobs
   of 30, so "within 5" is never called "better".
- Money: start the factory at the low end (~$3-4); keep ~$5 reserved for a training retry (memory / vLLM LoRA risks).
  Steps 2-5 each need the user's yes.
