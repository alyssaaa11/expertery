## Goal
A second-look exam arm "FTX": the trained model (FT, served by deploy/modal_forge.py, model FT_MODEL, endpoint from
FORGE_URL/FORGE_KEY) answers with the FT prompt (`ft_messages(job_text)`: short system prompt + job text, no manual,
no hint, no examples) and then gets EXACTLY the same fix loop as arm BX in `do_bx_cloud_call`: up to
`runner.BX_MAX_CALLS` (3) model calls; after a crash the user message is `runner.bx_error_message(run_error)`; after a
build the user message is `runner.bx_self_check_message(measure)`; "DONE" (no code fence) ends; the best built part is
graded by the cloud grader exactly as BX.

## Changes
1. `do_bx_cloud_call(...)`: add two keyword args with defaults that keep today's behaviour byte-identical:
   `messages=None` (if given, use a copy of it as the starting message list instead of
   `runner.build_messages("BX", ...)`) and `arm_label=BX_ARM` (written to the "arm" field of every round record and
   of the final record). Nothing else in the function changes.
2. New constant `FTX_ARM = "FTX"`.
3. CLI: new flag `--bx-loop` (store_true). Allowed only with `--arms FT` (exactly), not with --fill-missing, --hints or
   --selffix (parser.error otherwise). When set, each (job, rep) runs
   `do_bx_cloud_call(job, FT_MODEL, <forge endpoint>, secrets, "", post_fn, sleep_fn, exec_fn, grade_fn, exam=exam,
   rep=rep, messages=ft_messages(job["text"]), arm_label=FTX_ARM)` through the same `run_pairs` machinery that
   run_bx_fill uses (final record + rounds written to calls.jsonl; final has bx_final True), arm label "FTX" in
   calls.jsonl and summary.json. Budget, workers, k, gpu_start handling exactly as the FT path.
4. `finals_for`-style consumers: records of arm FTX with bx_final True are the finals (same rule as BX).
